# 문갑도 수거 작업 계획 페이지 · v2 (검토 반영판)

`문갑도_수거계획_v2.html` 은 GitHub Pages 에 올라가 있는 `index.html` (litter3d collect 산출물) 의 **로컬 사본**에
검토 의견을 반영한 것이다. 원본 데이터(42개 물체, 정사영상, 지형 격자)는 그대로이고 로직·문구만 바꿨다.

> 이 파일을 수정해도 https://jihu0629.github.io/aerodrone_hackathon/ 은 바뀌지 않는다.
> 링크를 바꾸려면 `aerodrone_hackathon` 저장소 `gh-pages` 브랜치의 `index.html` 자리에 올려야 한다.

## 바뀐 점

| 항목 | 전 | 후 |
|---|---|---|
| 기업 제공 무게 | "기업값" 토글, kg 로 표시 (42개 합계 1.3 kg) | "기업 지수 (참고)" 로 이름 변경, 선택하면 빨간 경고. kg 가 아니라고 명시 |
| 스티로폼 무게 | 면적 × 두께 × 밀도 (최소~최대 약 90배) | **부표 모드** (기본 켜짐): 면적 0.5 m² 이상 스티로폼은 부표 묶음으로 보고 개수(면적 ÷ 0.5 m²) × 개당 1.0 / 2.0 / 5.0 kg. 전체 범위 약 14배로 축소. 고급 설정에서 값 변경·해제 가능 |
| 중복 검출 | 없음 | 같은 종류가 1.5 m 안에 또 있으면 "중복 의심" 표시 (물체 표·팝업·구역 경고). 고급 설정에서 뒤쪽 것을 제외 가능 |
| 물때 | 체크리스트 한 줄 | 구역 카드 / 구역 패널의 **🌊 만조 주의** 버튼으로 구역 표시. 경고 문구·CSV 주의 열에 포함, 고급 설정에서 제외 가능. 표시는 공유 동기화됨 |
| 공유 동기화 충돌 | 마지막 저장이 전체를 덮어씀 (두 팀이 동시에 완료 처리하면 한쪽 소실) | 물체별 "마지막 변경 시각" 으로 **항목별 병합**. 보정 계수는 재질별, 출발지는 최신 시각 우선. 예전 형식 데이터도 읽음 |
| 문구 | "claude.ai 공개 링크에서는…" (Pages 에서는 해당 없음) | 공유 동기화 기준으로 수정 |
| 오프라인 | 지도 라이브러리 못 받으면 인쇄용 지도 | 안내 문구에 "출발 전 한 번 열어 두기" 추가 (unpkg 는 1년 캐시) |
| 기타 | 1인 운반 마대 수 기본값 코드 3 / 화면 2 불일치 | 2 로 통일 |

## 기본값이 바뀌므로 숫자가 달라진다

| | 대표 | 범위 |
|---|---|---|
| 기존(gh-pages) | 100.5 kg | 14.8 – 1,328 kg |
| v2 부표 모드 | 약 257 kg | 110 – 1,545 kg |

부표 모드의 개당 무게·바닥 면적은 **가정값**이다. 첫날 한 구역을 저울로 재서 "실측 보정" 을 쓰면 계수가 자동으로 잡힌다.
기존 숫자로 돌아가려면 고급 설정에서 "스티로폼 부표 모드" 를 끄면 된다.

## Supabase 공유를 켤 때

이 사본은 `"supabase": null` 이라 공유 동기화가 꺼져 있다. 켜려면

1. Supabase 대시보드 → SQL Editor 에서 `supabase_setup.sql` 실행 (테이블 + RLS 정책 + 실시간 publication).
2. `window.PLAN` 의 `"supabase": null` 을 gh-pages 판과 같은 `{ "url": "...", "key": "sb_publishable_...", "table": "shared_state" }` 로 바꾸고,
   `<head>` 에 `@supabase/supabase-js` 스크립트 태그를 추가한다 (gh-pages 판 `index.html` 의 `<head>` 참고).
3. publishable 키는 공개용이지만 보안은 전적으로 RLS 에 달려 있다. `supabase_setup.sql` 의 정책은
   읽기 모두 허용 / 쓰기는 `site='문갑도'` 한 행만 / 삭제 불가 / data 200 KB 제한이다.

## 직접 고치고 싶을 때: `src/` 와 `build.py`

1.4 MB 단일 HTML 은 이미지가 base64 로 들어 있어 편집기에서 다루기 힘들다. 그래서 네 조각으로 나눠 두었다.

| 파일 | 내용 | 고칠 때 |
|---|---|---|
| `src/app.js` (약 2,000줄) | 계산·표시·동기화 로직 전부 | 무게 공식, 경로, 카드 내용, 동기화 |
| `src/styles.css` | 모양 | 색, 글자 크기, 인쇄 |
| `src/index.src.html` | 화면 구조 (설정 입력, 카드, 표 머리글, 가정 설명) | 입력 항목 추가, 문구 |
| `src/plan.json` | 데이터 (물체 42개, 재질 가정값, 지형 격자, 이미지) | 밀도·두께 가정값, 기본값 |

고친 뒤 합치기:

```bash
cd "항공드론 해커톤/수거계획"
python3 build.py        # → 문갑도_수거계획_v2.html 을 다시 만든다
```

`build.py` 는 `plan.json` 이 올바른 JSON 인지 먼저 확인하고, 세 자리표시자(`<!--@@STYLES@@-->`, `<!--@@PLAN@@-->`, `<!--@@APP@@-->`) 에 끼워 넣는다.
분리 직후 다시 합친 결과는 원본과 바이트 단위로 같았다.

### 확인 방법

- 문법: `node -e "new Function(require('fs').readFileSync('src/app.js','utf8'))"`
- 동작: 합친 HTML 을 브라우저에서 열고 상단 "… ms 에 다시 계산" 이 뜨는지, 빨간 "계산 오류" 가 없는지 본다. 개발자 도구(F12) Console 에 오류가 있으면 줄 번호가 `app.js` 기준이 아니라 합친 HTML 기준이므로, 합친 파일에서 `(function() {` 가 시작하는 줄을 빼면 `app.js` 줄이 된다.
