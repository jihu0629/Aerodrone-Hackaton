# 해안쓰레기 수거계획 — 방향 정리 (2026-09-30)

> 과제 방향 전환: 정합·변화탐지 → **드론 영상 기반 해안쓰레기 위치·무게 추정 + 수거계획**
> 업체가 드론 영상 + 쓰레기 라벨 + 무게 기록을 제공할 예정.

## 0. 현장 문제 (업체 제보)

수거자가 힘들어하는 이유 두 가지:

1. **위치가 안 맞음** — 탐지된 위치와 실제 쓰레기 위치가 **50 m씩 어긋남**
2. **크기·무게를 모름** — 2D 이미지만 보고 가니 부피가 생각보다 크거나 무게가 생각보다 훨씬 무거움

→ 우리가 둘 다 해결한다는 게 발표 스토리.

---

## 1. 위치 오차 50 m — 원인

업체의 위치 추출 방식은 아직 모름. 흔한 원인을 영향이 큰 순서대로 정리함.

| 원인 | 어긋나는 정도 (예시) |
|---|---|
| **사진을 찍은 드론의 GPS를 쓰레기 위치로 기록** (화면 속 쓰레기 위치를 반영 안 함) | 고도 40 m면 한 장이 약 60×40 m를 덮음 → 화면 가장자리 쓰레기는 **30 m 이상** 어긋남 |
| **카메라가 비스듬히 찍음** (짐벌이 아래를 수직으로 안 봄) | 고도 40 m, 45° 기울기면 화면 중앙만 해도 드론 바로 아래에서 **40 m 앞** |
| 동영상과 GPS 로그(SRT)의 시간이 안 맞음 | 드론이 초속 10 m로 날면 **1초 어긋날 때마다 10 m** |
| 드론 방향(yaw) 오차 | 5° 틀리면 50 m 떨어진 지점에서 약 4 m |
| 일반 드론 GPS 자체 오차 | 2–5 m |
| 촬영 후 수거까지 쓰레기가 이동 | 가벼운 스티로폼은 바람·조수에 떠밀림 |

앞의 두 가지가 겹치면 50 m는 충분히 나오는 숫자.

## 2. 위치 오차 — 해결책 (기존 작업 재활용)

1. **픽셀 단위로 좌표 매기기** — SfM(ODM)으로 정사영상을 만들면 모든 픽셀에 실제 좌표가 붙음. 쓰레기 마스크의 중심이 곧 정확한 좌표. 3D 부피 계산용으로 어차피 만드는 결과물이라 추가 비용 없음.
2. **사진이 한두 장뿐일 때** — 짐벌 각도·고도·방향으로 픽셀에서 지면까지 선을 쏴서 좌표 계산. 이미 만든 `pipeline/01_drone_view_rectify.py`(경사 → 수직 보정) 활용.
3. **절대 위치 보정** — 드론 정사영상을 SkySat 위성영상에 LoFTR로 정합해서 전체적으로 밀린 위치를 바로잡음. SkySat↔Sentinel-2 정합에서 이미 인라이어 85%, 어긋남 5~8 m 수준 확인 (README ⑦).
4. **위치 오차를 같이 표시** — "이 쓰레기는 반경 ○ m 안"처럼 오차 원을 함께 보여줌.
5. **현장용 사진 카드** — 좌표와 함께 쓰레기 주변을 잘라낸 사진(바위·구조물 같은 표지물 포함) 제공. 수거자가 도착해서 눈으로 바로 찾을 수 있음.

→ 정합은 과제에서 빠졌지만 **"위치를 정확히 찍는 엔진"으로 재활용**.

## 3. 무게 추정 — 선행연구에서 확인한 빈칸

| 논문 | 실제 내용 | 우리가 이길 수 있는 지점 |
|---|---|---|
| Andriolo et al. 2024 (무게 3방법) | 제일 좋은 방법이 **"사람이 개수를 세고 × 평균 14 g"**, 정확도 약 80%. 저자들 스스로 "첫 시도라 신뢰성을 더 높여야 한다"고 씀 | 가장 좋은 방법조차 사람이 세고 평균을 곱하는 수준. 물체 하나하나의 무게는 아무도 안 냄 |
| Andriolo & Gonçalves 2024 (리뷰) | 1개 평균 19.5 **± 20.3** g, 중앙값 13.4 g | 표준편차가 평균만큼 큼 → 평균값 방식은 무거운 물체를 전혀 설명 못 함. **"생각보다 무거움"의 원인** |
| Kako et al. 2020 | SfM 3D 모델로 부피 오차 5% 미만 (크기를 아는 시험용 물체로 검증) | 부피에서 멈춤. 무게·작업량까지는 안 감 |
| PLAS-Net 2026 (arXiv 2604.21313) | 분할 결과로 **면적**만 계산. "어구는 개수로는 적지만 개당 면적은 가장 큼" | 면적까지만 감 |
| 수거 경로 연구 (JRM, TRASH) | 드론 검출 → 위치 군집화 → 로봇 경로 계획 | 모든 쓰레기를 **같은 무게의 점**으로 취급 |

→ **"물체마다 무게 + 수거 난이도"를 내는 연구는 아직 없음.**

참고 사례 — 드론 SfM 점군에서 부피 특징을 뽑아 실측 체중으로 회귀한 소 체중 추정은 평균 오차 약 2.3% (Embrapa, ICEIS 2026). 돼지 점군 + PointNet은 r = 0.97. **"3D 특징 + 실측 무게로 회귀"는 축산에서 이미 검증됐지만 해양쓰레기에는 적용 사례 없음.**

## 4. 창의성 포인트

1. **물리 모델 + 학습 모델 하이브리드 무게 추정**
   - 1단계: 물리 추정값 = 부피(3D) × 클래스별 밀도
   - 2단계: 업체 무게 데이터로 보정값을 학습. 입력 특징은 클래스·면적·높이·젖음 여부 등
   - 데이터가 적어도 물리 모델이 바닥을 받쳐주고, 데이터가 많아질수록 정확해지는 구조
2. **"몇 kg"이 아니라 "최대 몇 kg일 수 있는지"를 출력 (안전 기준)**
   - 예측 구간을 함께 냄 (conformal prediction). 예: "이 어망 뭉치 15–32 kg"
   - 구간의 위쪽 끝이 **23 kg(NIOSH 기준)** 을 넘으면 2인이나 장비 권장
3. **묻힘 의심 경고**
   - DSM에서 면적은 넓은데 높이가 거의 없는 어망·로프 → 모래에 묻혔을 가능성
   - "보이는 것보다 무거울 수 있음 / 삽 필요" 태그. 3D가 있어야만 가능
4. **결과를 좌표 목록이 아니라 "작업 카드"로 출력**
   - 예: "A구역 · 폐어망 뭉치 · 약 25 kg(최대 32) · 2인+절단기 · 묻힘 의심 · 위치 반경 3 m + 주변 사진"
   - 무게와 부피 중 먼저 차는 쪽으로 마대·트럭 수 계산, 무거운 격자부터 경로 계획

## 5. 발표 핵심 슬라이드

같은 업체 데이터에서 방법별로 비교(어블레이션):

- **위치**: 기존 방식 50 m → 우리 방식 ○ m
- **무게 오차**: 개수 × 14 g (Andriolo 방식) → 2D 면적 기반 회귀 → **+3D 특징**
- **23 kg 이상 물체를 놓치는 비율**: ○% → ○%

스토리: 현장 수거자가 힘들다 → 원인은 위치 오차와 평균값 추정 → 우리는 정확한 위치 + 물체별 무게·최대 무게로 해결.

## 6. 진행 순서

1. 업체 데이터 수령 → **위치 오차부터 측정** (기존 코드로 금방 가능, 발표 첫 장의 숫자)
2. 2D만으로 먼저 끝까지 돌리기: 분할 → 면적·클래스 → 무게 회귀 → 작업 카드
3. 영상이 겹쳐 찍혀 있으면 3D 특징 추가 (SfM → DSM → 부피)
4. 최대 무게 기준, 묻힘 경고 붙이기

→ 3D 복원이 실패해도 발표할 결과물은 남음.

## 7. 업체에 확인할 것

**위치 관련**
- [ ] 지금 쓰레기 위치를 **어떻게** 뽑고 있는지 (드론 GPS 그대로? 정사영상에서?)
- [ ] **실제로 수거한 지점의 GPS 기록**이 있는지 → 있으면 "기존 50 m → 우리 방식 ○ m" 정량 비교 가능
- [ ] 영상에 SRT·EXIF 텔레메트리(짐벌 각도·고도·방향)가 남아 있는지

**무게 관련**
- [ ] 무게가 **물체마다** 적혀 있는지, 구역 전체 합계만 있는지
- [ ] 라벨 박스와 무게 기록이 **같은 물체끼리 연결**되는지 (같은 ID)
- [ ] 무게가 적힌 물체가 **몇 개**인지 (수백 개 미만이면 딥러닝보다 GBM 같은 가벼운 회귀 + 물리 모델)
- [ ] 젖은 상태에서 잰 무게인지 (어망·로프는 차이가 큼)
- [ ] 영상이 **겹쳐 찍혀서** 3D 복원이 가능한지
